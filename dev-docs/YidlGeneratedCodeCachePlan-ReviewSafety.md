## 1. Findings

### P2-1 — Dependency identity is not bound to the generator snapshot actually used

**Location:** `yidl/dev-docs/YidlGeneratedCodeCachePlan.md:61–67`, together with miss publication at lines 69–70 and acceptance at line 185.

**Root cause and violated invariant:** The plan requires once-per-process dependency hashes and invalidation after source edits, but does not require those hashes to identify the dependency snapshot actually used by the deferred producer. An artifact must never be published under a revision different from the code/templates that generated it. Hashing files and later importing them are separate operations.

**Concrete sequence permitted by the text:**
1. Process A computes and memoizes dependency digest D1 while the generated Lifecycle assembly module is revision G1. It does not import that heavy module, as required for warm-hit lookup.
2. A developer replaces the generated module with G2, changing a template’s emitted behavior.
3. A encounters a miss for definition X. The deferred generation path imports G2 and compiles its output. The pinned implementation makes this lazy boundary explicit: `lifecycle.py:77–81` calls `_generated_lifecycle_base_module()`, whose import occurs at lines 167–170.
4. A publishes G2-generated code under its memoized D1 request identity.
5. The checkout is returned to G1. Fresh process B computes D1 and requests X. The envelope’s identity, compatibility, length, and checksum all match, yet B executes G2-generated code instead of G1 output.

**Impact:** A normal source-edit interleaving can poison a persistent identity with another generator revision. Later processes can reuse incorrect generated behavior even though all specified envelope checks pass. This is a proposed-plan correctness defect, not a claim of active runtime corruption.

**Required correction — bounded:** Require coherence between request identity and the actual producer dependency snapshot, including already-loaded modules and deferred imports. Define a safe source-checkout policy: establish an immutable producer epoch with verifiable provenance, or bypass publication/reuse when coherence cannot be established. Merely rehashing current disk files does not establish the provenance of already-loaded Python modules. State how dependency changes invalidate the memoized epoch.

**Closure test:** Add a required future fault case that pauses after fingerprinting, replaces the lazily imported generator, resumes a miss, restores the original generator, and starts a fresh reader. No artifact generated by G2 may be accepted under D1. Include the reverse case where G1 is already loaded before disk files become G2. Plan-review closure requires an explicit policy and these acceptance sequences, not implemented tests now.
