## Safe removal and retained references

Field-local policy belongs with that field declaration/fact. Removing a field
must remove its slot/parameter/store/selection facts together. SlotNames is
consumer-normalized in this tutorial, so removing only a FieldRow is not a
complete deletion operation. A remaining named factory dependency must fail as
a missing dependency; it must not silently bind the next field.

Dataclass's fixed-revision `dataclass_field_removal` canonical case records a
richer before/after deletion with independent behavior and a retained-reference
diagnostic. See [consumer provenance](consumers.md). That consumer-specific
normalizer is not generalized into a new YIDL field-removal API here.

For default/factory/keyword-only/accessor output consult the fixed consumer
resources and generated outputs there. They supplement the minimal generic
example, with their own exact verification boundary.
